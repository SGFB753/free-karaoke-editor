KARAOKE ON A NEW VIRTUAL MACHINE — STEP BY STEP

All of this is done once. It takes about twenty minutes, fifteen
of which are the libraries downloading.


STEP 0. WHICH VM TO TAKE
========================

  System    Ubuntu 22.04 or 24.04 (the easiest)
  Memory    16 GB — everything works
             8 GB — everything but the large-v3 model
             4 GB — only without the instrumental, the --light option
  Disk      20 GB
  Cores     4, better 8
  Graphics  not needed; with an NVIDIA card it is 5-10 times faster

Memory is the only thing people stumble over. The instrumental needs
about 4 GB, timing with small about 2 GB.


STEP 1. LOG IN TO THE VM
========================

From Windows, in the ordinary command line (PowerShell):

    ssh user@vm-address

If ssh is not found — turn it on:
Settings -> Apps -> Optional features ->
Add a feature -> OpenSSH Client.


STEP 2. COPY THE PROGRAM TO THE VM
==================================

Way A. Copy it from your computer.
In PowerShell on YOUR machine (not on the VM):

    scp -r D:\karaoke user@vm-address:~/karaoke

Way B. If the folder is not at hand — unpack the archive with the
program right on the VM:

    unzip karaoke.zip

The "projects" folder need not be copied, it is recreated.


STEP 3. RUN THE INSTALLER
=========================

On the VM:

    cd ~/karaoke
    bash install-on-server.sh

The script installs ffmpeg and Python itself, creates a separate
environment and pulls in the libraries. The options:

    bash install-on-server.sh --gpu     there is an NVIDIA card
    bash install-on-server.sh --light   no instrumental, frugal
    bash install-on-server.sh --models  download the models right away

The --models option is useful if you would rather wait through all the
downloads at once than meet them on the first song.

The script can be run again — what is already installed is not broken.

At the end it checks by itself that everything landed and prints what to
do next. If memory is short — it tells you how to add a swap file.


STEP 4. UPLOAD A SONG AND ITS LYRICS
====================================

In PowerShell on YOUR machine:

    scp "D:\karaoke\song.mp3" "D:\karaoke\song.txt" user@vm-address:~/karaoke/


STEP 5. BUILD
=============

On the VM:

    cd ~/karaoke
    source .venv/bin/activate
    python3 app/karaoke.py "song.mp3" "song.txt" -o "karaoke.html"

The first run takes longer than the rest: the Whisper model is downloaded.

Useful options:

    --whisper-model medium   more accurate, needs ~4.5 GB of memory
    --whisper-model large-v3 the best accuracy, needs ~8 GB
    --device cuda            compute on the graphics card
    --no-separate            no instrumental, twice as fast

The video:

    python3 app/tools/video.py "karaoke.html"

Many songs at once — put them in one folder with matching names
(Wind.mp3 + Wind.txt):

    python3 tools/auto.py ~/karaoke/songs


STEP 6. FETCH THE RESULT
========================

In PowerShell on YOUR machine:

    scp user@vm-address:~/karaoke/*.html D:\done\
    scp user@vm-address:~/karaoke/*.mp4  D:\done\


IF YOU WANT THE STUDIO WINDOW
=============================

The studio listens to itself only and does not stick out — deliberately:
it has no passwords, and it can read files. You reach it through a
tunnel.

In PowerShell on YOUR machine:

    ssh -L 8770:127.0.0.1:8770 user@vm-address

In the same window, on the VM now:

    cd ~/karaoke && source .venv/bin/activate && python3 app/studio.py

Then open in your own browser:  http://127.0.0.1:8770/

Do NOT open the studio port to the network.


THE MODELS DO NOT DOWNLOAD
==========================

The models are pulled from the internet on the first run: Whisper 75 MB
to 3 GB, Demucs about 80 MB. The program says in plain words what exactly
failed to download, and goes on without the instrumental if that is what
it was.

Download in advance:   bash install-on-server.sh --models

The cache lives in ~/.cache/whisper and ~/.cache/torch/hub/checkpoints —
it can be carried over from another machine so nothing is downloaded twice.

IMPORTANT ABOUT THE INSTRUMENTAL: besides demucs the soundfile package is
needed. Without it Demucs finishes the separation and then fails while
writing the result. The install script puts it in itself; by hand it is
pip install soundfile


IF SOMETHING WENT WRONG
=======================

Not enough memory (WinError-like messages, "not enough memory", the
process killed) — add a swap file:

    sudo fallocate -l 8G /swapfile
    sudo chmod 600 /swapfile
    sudo mkswap /swapfile
    sudo swapon /swapfile

To check that everything is intact:

    cd ~/karaoke && source .venv/bin/activate
    python3 tests/test_pipeline.py

We expect "All checks passed".

To check piece by piece:

    python3 -c "import stable_whisper; print('timing ok')"
    python3 -c "import demucs, soundfile; print('instrumental ok')"
    python3 -c "from PIL import Image; print('video ok')"


HOW LONG TO WAIT
================

A 3.5-minute song:

    4 cores, no graphics card     ~5 minutes
    8 cores, no graphics card     ~3 minutes
    with NVIDIA                   under a minute

With the --no-separate option it is roughly twice as fast.
